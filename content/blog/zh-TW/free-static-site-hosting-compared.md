**TL;DR：** 對一個面向全球讀者的個人靜態網站來說，**Cloudflare Pages** 是最強的預設選擇——免費頻寬無上限，全球延遲也最好。**GitHub Pages** 最簡單，如果你的 repo 本來就放在 GitHub。**Vercel** 的 Next.js 體驗最順滑，**Netlify** 則介於中間，預覽工作流程打磨得最細。對這樣的部落格來說，四家都是真·免費。

「免費託管」在過去意味著你的 GeoCities 頁面頂上掛一條橫幅廣告。今天，各大靜態主機的免費方案好得離譜——存在的原因很簡單：今天的業餘玩家就是明天的創業者。以下是四家主流業者對一個真實個人網站在 2026 年的比較。

## 參賽選手

### Cloudflare Pages

- **免費方案：** 頻寬無上限，每月 500 次 build，站點數無上限
- **速度：** 這就是它的賣點——Cloudflare 的網路基本上和地球上每一家 ISP 都有互連
- **工作流程：** 連接 GitHub repo，build 指令 `npm run build`，輸出目錄 `out`
- **注意：** build 分鐘數在專案之間共用；重量級 monorepo 可能會頂到上限

**最適合：** 面向全球讀者的網站。如果你的讀者分布在不同大洲，這份名單上沒有別家能匹配它的延遲，而且沒有頻寬天花板意味著上了 Hacker News 首頁也一分錢都不用多花。

### GitHub Pages

- **免費方案：** 每月 100GB 軟性頻寬上限，repo 大小 1GB，公開 repo 無限
- **速度：** 背靠 Fastly 的 CDN——真的很快，只是邊緣節點覆蓋比 Cloudflare 略薄
- **工作流程：** 現成的 GitHub Actions workflow，每次 commit 自動推送 `out/` 資料夾
- **注意：** 1GB 的 repo 限制意味著大型圖庫應該放 Git LFS 或別處

**最適合：** 和程式碼住在一起的開發者部落格。一個平台、一張帳單（金額為零），而且 `username.github.io` 是個大家一看就知道是你的網域。

### Vercel

- **免費方案：** 每月 100GB 頻寬，個人使用的 build 額度很寬裕
- **速度：** 優異，有聰明的邊緣快取
- **工作流程：** Next.js 零設定——push 就部署，每個 PR 都有預覽
- **注意：** hobby 方案限非商業用途；商業使用預期要升級到 $20/席的方案

**最適合：** 用到伺服器功能（ISR、函式、圖片最佳化）的 Next.js 應用。純靜態匯出也能用——只是 Vercel 賣的大部分東西你都用不上。

### Netlify

- **免費方案：** 每月 100GB 頻寬，300 分鐘 build 時間
- **速度：** 全球 CDN 表現紮實
- **工作流程：** 拖拉即部署、每個 PR 有預覽連結、各種貼心小功能
- **注意：** 如果每張圖片的 commit 都觸發重建，300 分鐘會燒得出奇地快

**最適合：** 喜歡預覽 URL 工作流程、或想不碰終端機就一鍵回滾的人。

## 正面對決

|                     | Cloudflare Pages | GitHub Pages | Vercel      | Netlify     |
| ------------------- | ---------------- | ------------ | ----------- | ----------- |
| 免費頻寬            | **無上限**       | 100GB/月     | 100GB/月    | 100GB/月    |
| 免費 build          | 500 次/月        | 經 Actions   | 寬裕        | 300 分鐘/月 |
| 全球延遲            | **最佳**         | 極佳         | 極佳        | 極佳        |
| 上手成本            | 低               | 中           | **最低**    | 低          |
| 免費子網域          | .pages.dev       | .github.io   | .vercel.app | .netlify.app|
| 商業用途            | 允許             | 允許         | 僅限 hobby  | 允許        |

## 我的建議

1. **預設選擇：Cloudflare Pages。** 免費頻寬無上限加上最廣的邊緣網路，對國際讀者來說很難反駁。
2. **如果網站和程式碼住一起：GitHub Pages。** Actions workflow 是已經被解決的問題，心智負擔為零。
3. **如果未來可能超出純靜態：Vercel。** 從靜態起步、之後再加伺服器功能，只是五行程式碼的改動。

最後提醒一句：無論選哪家，把內容以 Markdown 放進 git repo，就像這個網站一樣。主機來來去去，一個純文字檔案夾才是永遠的。
